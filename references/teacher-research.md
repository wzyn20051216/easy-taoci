# 导师检索与排序

## 目标

检索的目标不是堆很多姓名，而是建立覆盖尽量完整、证据可追溯、能按联系价值排序的候选池。对教师方向和招生状态的判断可能随时间变化，因此每次任务都要重新核验。

## 来源优先级

1. 学院教师名录、研究生导师目录、学校教师主页。
2. 学院实验室、全国重点实验室或官方团队页面。
3. 学校招生目录、教师近期招生公告、官方个人主页动态。
4. ORCID、DBLP、Google Scholar 等只用于理解近期研究，不用于确认邮箱或招生状态。
5. 搜索引擎摘要、聚合站和自媒体只用于定位，不能作为最终证据。

同一条事实出现冲突时，保留两个来源和核验日期，优先采用更近期、更直接的官方页面，并把不确定性写进 `research_notes`。

## 两遍检索

### 第一遍：覆盖

从学院入口枚举所有相关教师，不要在看到前几位匹配老师后提前停止。记录名录分页、系所、团队和职称筛选条件。对以下候选直接标记但暂不删除：

- 页面没有邮箱；
- 方向只写宽泛关键词；
- 导师身份不明确；
- 页面多年未更新。

保留这些候选可以防止覆盖偏差，第二遍再补证据和降级。

### 第二遍：补证据

逐位打开教师页，提取：

- 当前研究方向，而不是只看历史论文题目；
- 官方邮箱，多个邮箱保留顺序；
- 团队、实验室、导师身份；
- 最近 18 个月内的招生或学生招募信息；
- 页面更新时间或本次核验日期。

招生状态采用保守分类：

- `confirmed`：近期官方页面明确招收对应年份/项目学生。
- `likely`：身份和团队信息支持招生，但没有近期明确公告。
- `unknown`：证据不足。
- `not_recruiting`：官方明确暂停招生、已退休或不招对应类别。

## 查询模板

```text
<学校> <学院> 师资队伍
<学校> <学院> 研究生导师
site:<学校官方域名> <姓名> 邮箱
site:<学校官方域名> <姓名> 招生 2027
site:<学校官方域名> <研究方向> 教师
```

当前年份和申请年份必须来自任务上下文，不能沿用旧批次。

## 标签归一化

使用少量稳定英文标签连接学生经历和导师方向，例如：

| 方向 | 标签示例 |
| --- | --- |
| 无线通信、6G、网络 | wireless;communication;networking |
| 信号处理、雷达 | signal-processing;radar |
| 嵌入式、物联网、边缘设备 | embedded;iot;edge-ai |
| 计算机视觉、目标检测 | computer-vision;object-detection |
| 机器人、控制 | robotics;control |
| 信息安全、可信感知 | security;authentication |

标签只用于候选排序。最终匹配理由必须回到具体事实和研究内容，不能把标签重合直接写成“高度匹配”。

## 排序解释

默认总分 100：

- 方向与学生证据标签：55 分。
- 招生证据：20 分。
- 来源质量与新鲜度：15 分。
- 邮箱可用性：10 分。

以下情况应硬降级：

- `contact_status` 已是 `sent`、`saved`、`replied` 或 `skipped`；
- `admission_status=not_recruiting`；
- 没有官方来源；
- 没有任何学生证据可支撑匹配。

分数旁必须保留 `score_reasons`，让用户知道加分和降级来自哪里。

## 质量抽查

每批至少抽查最高分、边界分和最低分各一位：

- 最高分是否因泛化标签虚高；
- 边界候选是否有遗漏的学生经历；
- 最低分是否因官网字段缺失被误伤；
- 招生证据是否属于当前申请周期；
- 邮箱是否来自官方页面而非推测。
